# Risks

Things that can go wrong in this sync tool, why, and what guards against each. Read this before changing capture, apply, profiles, the shims or the publish script. Each entry names the test that covers it.

| # | Risk | Cause | Guard | Test |
|---|---|---|---|---|
| 1 | Profile entry overwritten on restore | `sync` captures before it applies. A profile entry pulled from the repo but not applied yet looks identical to the shared file locally, so a naive copy-back would overwrite the profile with the shared version. | Copy back only when the live entry differs from the applied-state stamp (`.claude-sync-applied-profile`). No stamp record means "not applied yet", so the profile is left alone. | `tests/profile.bats` (capture-before-apply regression), `tests/py/test_profile.py` (`test_restored_machine_first_capture_keeps_unapplied_profile_entry`, `test_crash_before_the_stamp_rename_reads_as_not_applied`, `test_crash_after_unapply_reads_as_not_applied`) |
| 2 | Profile content leaks into shared files | Capture's mirror copy (`rsync --delete` in the legacy bash) copies everything under `~/.claude/agents`, `hooks` and `~/.agents/skills` into the shared directories. | Names owned by the profile (entries, `.disabled` markers, stamp names) are excluded from the shared capture, and the shared copy is never deleted for them. `CLAUDE.md` is captured without the append block. | `tests/profile.bats`, `tests/sync_files.bats`, `tests/py/test_profile.py` (`test_agents_replace_add_and_disable_without_leaking`, `test_local_edit_goes_back_into_the_profile_not_the_shared_copy`, `test_claude_md_block_appended_after_marker_and_stripped_before_capture`), `tests/py/test_syncfiles.py` (`test_capture_with_excludes_neither_copies_nor_deletes`, `test_excluded_name_survives_delete`) |
| 3 | Capture refuses to run (deadlock) | `live_matches_commit` rebuilds what a clean apply would leave and diffs it with live. If it ignores the profile, an applied profile looks like a local edit and capture is refused. | It rebuilds the expected tree with the stamped profile applied. | `tests/profile.bats`, `tests/py/test_gitflow.py` (`test_a_moved_clone_with_an_applied_profile_skips_capture_not_refuses`) |
| 4 | Shared file not restored after a profile entry is removed | Legacy bash: rsync skips a file whose size and mtime match, so a shared file the same size as the old profile copy is not put back. The Python mirror compares bytes, so this premise is bash-only, but the guard stays in both. | `profile_unapply` removes last time's applied entries before `sync_apply`. | `tests/profile.bats`, `tests/py/test_profile.py` (`test_unapply_removes_only_what_the_last_apply_put_in_place`, `test_entry_removed_from_profile_reverts_and_stale_copy_is_not_captured`), `tests/py/test_syncfiles.py` (`test_same_size_and_mtime_different_content_is_detected`) |
| 5 | Dangling hook reference | A profile disables a hook script that `settings.json` still wires in, so the hook errors on every event. | `doctor` reports hook commands whose script is missing. | 6 | Hooks run unreviewed code | Hooks execute automatically. A shared hook change lands on every machine's next sync. Review hook changes like code. | `tests/profile.bats`, `tests/py/test_subcommands.py` (`test_profile_copy_shows_hooks_asks_first_and_needs_force_to_overwrite`, `test_profile_copy_with_no_answer_at_all_aborts`), `tests/py/test_profile.py` (`test_hook_scripts_are_executable_regular_files_sorted`) |
| 7 | Profile does not apply after a rename | The profile is keyed by hostname. New infrastructure with a different hostname silently gets no profile. | `PROFILE=<name>` in the machine conf, set by `install.sh --profile <name>` or `profile use <name>`. | `tests/profile.bats`, `tests/machine_conf.bats`, `tests/py/test_install.py` (`test_profile_flag_writes_profile_line_and_applies_that_profile`, `test_claude_sync_profile_works_like_the_flag`), `tests/py/test_subcommands.py` (`test_profile_use_points_the_machine_at_another_profile_and_applies_it`), `tests/py/test_machineconf.py` (`test_write_machine_profile_sets_replaces_and_removes`) |
| 8 | Per-machine or personal content published | The public mirror is generated from a whitelist in `publish-public.sh` (and its Python port `claude_sync/publish.py`); a careless whitelist edit could add `machines/`, `memory/`, `private/` or `weekly-review/`. | `assert_public_tree_clean` aborts the publish if any of them, or a nested `*.settings.json` under `machines/`, is in the generated tree. | 9 | `install.sh --repair` loses the profile, or pushes to the default branch | Repair rewrites the machine's `.conf`. | Repair keeps `machines/<profile>/` and the settings override. | 10 | Stuck sync | This machine's pending changes and a merged change edit the same lines, so the sync branch can't be rebuilt on the default branch. Every sync fails until it is resolved. A clone left with commits on the default branch by an older `claude-sync.sh` is the legacy form. | The conflict is reported loudly (files, how to resolve, how to drop), nothing is applied or pushed. Legacy commits are moved onto `sync/<hostname>`. `doctor` and `doctor remediate`. | `tests/sync_cli.bats` (real conflict, legacy commit), `tests/sync_pr.bats`, `tests/py/test_gitflow.py` (`test_a_real_conflict_fails_loudly_and_changes_nothing`, `test_migrate_moves_a_legacy_commit_off_the_default_branch`, `test_migrate_then_conflict_is_reported_and_live_kept`), `tests/py/test_doctor.py` (`test_doctor_remediate_clears_a_stuck_rebase`, `test_doctor_remediate_moves_a_legacy_commit_and_reports_a_real_conflict`) |
| 11 | Stale capture reverts merged work | Capture copies live files over the repo. This machine's own pending PR is the effective state, so it never causes a refusal. | 12 | Secrets committed | Account files are never copied, but a mistake could add one. | Denylist (`.credentials.json`, `.claude.json`), `.gitignore`, gitleaks in CI. | `tests/safety.bats`, `tests/py/test_safety.py` (`test_denylist_catches_credentials`, `test_match_at_depth_three`), `tests/py/test_gitflow.py` (`test_denylisted_file_refuses_the_commit`) |
| 13 | A push lands on the default branch | Every machine pushing to the default branch, with no review. | Nothing is committed on the default branch (commits are built with `commit-tree` onto `sync/<hostname>`); the push names `<sha>:refs/heads/sync/<hostname>` explicitly with `--force-with-lease`; the branch name must differ from the default branch. | 14 | Pending changes lost | The clone sits on the default branch while a PR is pending, so an apply from a plain default tree would revert this machine's own edits, and a rewrite of the working tree could drop hand edits. | The working tree holds the sync branch's tree (the index stays at HEAD, so nothing pending is staged). | 15 | A PR branch edited on GitHub is overwritten | Each sync force-pushes the sync branch. | The push is skipped and reported when origin's branch holds commits this machine did not push and that are not already merged. | `tests/sync_pr.bats`, `tests/py/test_pr.py` (`test_a_sync_branch_edited_on_github_is_not_overwritten`) |
| 16 | Sync PRs never converge after a merge | A squash merge rewrites the pending commit, so replaying it on the new default branch conflicts. | The sync branch is always one commit, rebuilt in two `merge-tree` steps: the pending state first (drops out when merged), then this run's commits. ## Known gaps

- Legacy bash only (`CLAUDE_SYNC_IMPL=bash`): entry names containing `*`, `?` or `[` are not escaped in the rsync exclude list. Profile entries should not use them there. The Python matches exclude names exactly.
- `install.sh --repair` refuses while a sync PR is pending (the clone looks dirty). Merge or drop the PR and sync first.
- A stale remote `sync/<hostname>` is only removed if GitHub deletes head branches on merge; the script never deletes remote branches. A kept, merged branch is ignored, then overwritten safely by the next push. On a fresh clone without a working `gh`, such a branch is adopted and can conflict; the message says how to drop it.
- `push` does not bring in the default branch, so a PR it opens can show already-merged content until the next `sync`.
- Legacy bash only (`CLAUDE_SYNC_IMPL=bash`): without `flock` the fallback lock can, in a rare three-way race over a dead owner's lock, let two runs in at once.
- `.gitattributes` still normalises line endings of profile files under `machines/<profile>/` (row 26). Existing Windows clones made with `core.autocrlf` on need a one-time re-checkout, and their live CRLF files converted to LF by hand or the change dropped from the PR (`docs/runbook.md`, "Re-check out a Windows clone").
- The bash `publish-public.sh` copies the working tree; files the exported `.gitignore` ignores are left out by its `git add -A`, and its dirty-tree check refuses untracked files, but a file ignored only by the source's `.git/info/exclude` or a global excludes file would be published. Prefer the Python publish.
- The Windows branches (lock, links and junctions, read-only removal, signals, the `.cmd` shims) run only in the Windows CI job and by hand (`docs/windows-manual-test.md`); some never run in CI. See the Windows checklist in `docs/python-port.md`.
- A power loss, a SIGKILL, or the Windows hook timeout while git runs can still leave a stale `.git/index.lock` or `.git/refs/remotes/origin/*.lock` (row 35 covers SIGTERM, SIGHUP and Ctrl-C); the next run then fails until it is removed by hand (`docs/runbook.md`).
- On Windows the hook timeout kills Python outright, with no handler run, so the run ends as after a power loss: the lock goes with the process, but the apply window and the applied record are not protected.
- `git stash`, `git reset --hard` or a manual `git commit` in the clone while a PR is pending can make the next sync's PR drop files that capture does not restore (e.g. a new `machines/<hostname>.conf`).
- An empty origin (no default branch) is refused; push an initial commit by hand.
- The hooks give the sync 20 s (`timeout 20`); fetch, push and two `gh` calls on a slow link can exceed it, which shows as a failed sync.
- `doctor` reports stale `.disabled` markers, dangling hook references and hooks tracked without the exec bit but does not fix them, since that means editing the shared repo.
- Auto-memory mixes global and project-specific entries; see the design spec.
- The weekly review's redaction is pattern based, so a secret in an unknown shape can reach the model or the issue. Read a `--dry-run-send` before creating the approval files.
