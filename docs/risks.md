# Risks

Things that can go wrong in this sync tool, why, and what guards against each. Read this before changing capture, apply, profiles or the publish script. Each entry names the test that covers it.

| # | Risk | Cause | Guard | Test |
|---|---|---|---|---|
| 1 | Profile entry overwritten on restore | `sync` captures before it applies. A profile entry pulled from the repo but not applied yet looks identical to the shared file locally, so a naive copy-back would overwrite the profile with the shared version. | Copy back only when the live entry differs from the applied-state stamp (`.claude-sync-applied-profile`). No stamp record means "not applied yet", so the profile is left alone. | `tests/profile.bats` (capture-before-apply regression) |
| 2 | Profile content leaks into shared files | `rsync --delete` capture copies everything under `~/.claude/agents`, `hooks` and `~/.agents/skills` into the shared directories. | Names owned by the profile (entries, `.disabled` markers, stamp names) are excluded from the shared capture, and the shared copy is never deleted for them. `CLAUDE.md` is captured without the append block. | `tests/profile.bats`, `tests/sync_files.bats` |
| 3 | Capture refuses to run (deadlock) | `live_matches_commit` rebuilds what a clean apply would leave and diffs it with live. If it ignores the profile, an applied profile looks like a local edit and capture is refused. | It rebuilds the expected tree with the stamped profile applied. | `tests/profile.bats` |
| 4 | Shared file not restored after a profile entry is removed | rsync skips a file whose size and mtime match, so a shared file the same size as the old profile copy is not put back. | `profile_unapply` removes last time's applied entries before `sync_apply`. | `tests/profile.bats` |
| 5 | Dangling hook reference | A profile disables a hook script that `settings.json` still wires in, so the hook errors on every event. | `doctor` reports hook commands whose script is missing. Disable the wiring with a settings override. | `tests/profile.bats` |
| 6 | Hooks run unreviewed code | Hooks execute automatically. A shared hook change lands on every machine's next sync. A profile hook runs on its own machine only, but `profile copy` and `PROFILE=` move it to another machine. | `profile copy` lists executable hooks and asks before copying (`--yes` skips). Review hook changes like code. | `tests/profile.bats` |
| 7 | Profile does not apply after a rename | The profile is keyed by hostname. New infrastructure with a different hostname silently gets no profile. | `PROFILE=<name>` in the machine conf, set by `install.sh --profile <name>` or `profile use <name>`. | `tests/profile.bats`, `tests/machine_conf.bats` |
| 8 | Per-machine or personal content published | The public mirror is generated from a whitelist in `publish-public.sh`; a careless whitelist edit could add `machines/`, `memory/`, `private/` or `weekly-review/`. | `assert_public_tree_clean` aborts the publish if any of them, or a nested `*.settings.json` under `machines/`, is in the generated tree. | `tests/safety.bats` |
| 9 | `install.sh --repair` loses the profile, or pushes to the default branch | Repair rewrites the machine's `.conf`. | Repair keeps `machines/<profile>/` and the settings override. The `PROFILE=` line must be given again with `--profile`. The `.conf` is only removed from the fresh clone's working tree; the new one goes out through the sync PR, so repair pushes nothing to the default branch. | `tests/profile.bats` (repair on a machine that synced before), `tests/sync_cli.bats` (repair) |
| 10 | Stuck sync | This machine's pending changes and a merged change edit the same lines, so the sync branch can't be rebuilt on the default branch. Every sync fails until it is resolved. A clone left with commits on the default branch by an older `claude-sync.sh` is the legacy form. | The conflict is reported loudly (files, how to resolve, how to drop), nothing is applied or pushed. Legacy commits are moved onto `sync/<hostname>`. `doctor` and `doctor remediate`. | `tests/sync_cli.bats` (real conflict, legacy commit), `tests/sync_pr.bats` |
| 11 | Stale capture reverts merged work | Capture copies live files over the repo. If live is older than the clone's effective state (the sync branch, else the default branch) it commits stale files. | `check_capture_is_safe` compares the applied-commit stamp's tree with the effective tree and skips or refuses capture. This machine's own pending PR is the effective state, so it never causes a refusal. The stamped commit is pinned as `refs/claude-sync/applied` so gc can't remove it; if it is missing anyway (a re-clone), capture is refused with its own message and the two ways out. | `tests/sync_cli.bats`, `tests/sync_pr.bats` (missing last-applied commit) |
| 12 | Secrets committed | Account files are never copied, but a mistake could add one. | Denylist (`.credentials.json`, `.claude.json`), `.gitignore`, gitleaks in CI. | `tests/safety.bats` |
| 13 | A push lands on the default branch | Every machine pushing to the default branch, with no review. | Nothing is committed on the default branch (commits are built with `commit-tree` onto `sync/<hostname>`); the push names `<sha>:refs/heads/sync/<hostname>` explicitly with `--force-with-lease`; the branch name must differ from the default branch. A human merges the PR; auto-merge is never set. | `tests/sync_pr.bats` |
| 14 | Pending changes lost | The clone sits on the default branch while a PR is pending, so an apply from a plain default tree would revert this machine's own edits, and a rewrite of the working tree could drop hand edits. | The working tree holds the sync branch's tree (the index stays at HEAD, so nothing pending is staged). Before any rewrite of the working tree everything in it is committed onto the sync branch, and the rewrite holds off INT/TERM/HUP. A fresh clone adopts this machine's open `sync/<hostname>` from origin. | `tests/sync_pr.bats` |
| 15 | A PR branch edited on GitHub is overwritten | Each sync force-pushes the sync branch. | The push is skipped and reported when origin's branch holds commits this machine did not push and that are not already merged. | `tests/sync_pr.bats` |
| 16 | Sync PRs never converge after a merge | A squash merge rewrites the pending commit, so replaying it on the new default branch conflicts. | The sync branch is always one commit, rebuilt in two `merge-tree` steps: the pending state first (drops out when merged), then this run's commits. An empty result deletes the local branch. A remote branch GitHub kept after the merge is not adopted again: not when its tip is the one this machine last pushed (`claude-sync.lastPushed`), and on a fresh clone not when `gh` shows a merged or closed PR at exactly that tip and none open. A branch with no PR at all (pushed while `gh` was missing) still holds pending changes and is adopted. If `gh` can't tell, it is adopted too, and a conflict message says how to drop it. | `tests/sync_pr.bats` (squash merge that kept the branch, fresh clone, branch pushed without a PR) |
| 17 | Two runs at once | One session's `SessionEnd` and another's `SessionStart` overlap. | `flock` on `.git/claude-sync.flock`: waits `CLAUDE_SYNC_LOCK_WAIT` s (default 10), then fails loudly; the kernel frees it when a run dies. git and gh run with the lock's fd closed, so a background `git gc` can't keep it. `doctor remediate` takes it too (and lets go around its nested sync). Without `flock`, a pid symlink lock created atomically, with a warning; a dead owner's lock is cleared by an atomic `mv`. Ref updates use compare-and-swap. | `tests/sync_pr.bats` (lock tests) |
| 18 | Silent failure | A hook runs the sync with output logged. | Every failure path prints what failed and what to do on stderr and exits non-zero; the hooks then show "claude-config sync failed". Every fetch failure gets the same specific message. A clone on a feature branch exits 0 but prints "sync SKIPPED" and why. | `tests/sync_pr.bats`, `tests/sync_cli.bats` (feature branch skip) |
| 19 | Old git misread | `merge-tree --write-tree` needs git 2.38 and `--merge-base` 2.40; an older git errors, and a git error could be mistaken for a conflict. | Every repo-changing command checks for git 2.40+ first and fails with the version found. merge-tree exit 1 is a conflict; any other failure is reported as a git error, never as a conflict. | `tests/sync_pr.bats` (old git, merge-tree failure) |

## Known gaps

- Entry names containing `*`, `?` or `[` are not escaped in the rsync exclude list. Profile entries should not use them.
- `install.sh --repair` refuses while a sync PR is pending (the clone looks dirty). Merge or drop the PR and sync first.
- A stale remote `sync/<hostname>` is only removed if GitHub deletes head branches on merge; the script never deletes remote branches. A kept, merged branch is ignored, then overwritten safely by the next push. On a fresh clone without a working `gh`, such a branch is adopted and can conflict; the message says how to drop it.
- `push` does not bring in the default branch, so a PR it opens can show already-merged content until the next `sync`.
- Without `flock` the fallback lock can, in a rare three-way race over a dead owner's lock, let two runs in at once.
- `git stash`, `git reset --hard` or a manual `git commit` in the clone while a PR is pending can make the next sync's PR drop files that capture does not restore (e.g. a new `machines/<hostname>.conf`).
- An empty origin (no default branch) is refused; push an initial commit by hand.
- The hooks give the sync 20 s (`timeout 20`); fetch, push and two `gh` calls on a slow link can exceed it, which shows as a failed sync.
- `doctor` reports stale `.disabled` markers and dangling hook references but does not fix them, since that means editing the shared repo.
- Auto-memory mixes global and project-specific entries; see the design spec.
